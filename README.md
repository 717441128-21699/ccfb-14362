# 八百里加急 · 驿路接力调度沙盘

主策划命题:八百里加急公文从京城到边关,驿卒须在 **3 个游戏日**内靠**换马接力**送达;
接力路线与每站换哪匹马必须**实时算出来,不能写死**;30 驿站、500 公文同时在途时,
一次全量重规划 **不超过 100ms**;途中下雨断路、马病倒、遇劫道要能重规划,**已跑出的一程不可撤回**。

本项目是一套零运行时依赖的 TypeScript 调度引擎 + Vite 可视化沙盘。

## 快速开始

```bash
npm install
npm run dev      # 打开沙盘(默认 http://localhost:5173)
npm test         # 23 个单元/不变量测试
npm run bench    # 500 单全量重规划性能基准
npm run build    # 类型检查 + 生产构建
```

## 四个页面

| 页面 | 能看什么 / 能做什么 |
| --- | --- |
| **驿路地图** | 30 驿站与随机驿路、地形与天气;彩色光点是在途公文(红=一等/橙=二等/灰=常规),沿当前程平滑移动。**点道路**封路/恢复、**点公文**触发劫道、**点驿站**进驿站页 |
| **驿站兵马** | 每站马匹体力条、驿卒疲劳条、可用/在骑/病倒/休整状态;可手动「弄病」一匹马,相关公文立即重规划 |
| **准时统计** | 累计派单、送达、总准时率、超时数、重规划次数、上次全量重规划耗时;分紧急等级准时率、事故分布、实际/计划用时比、事故时间线 |
| **规则调参** | 策划直接改体力消耗、恢复率、速度系数、地形系数、事故概率、各等级限时等;点「应用并全量重规划」**热更新即时生效**,下一单就按新规则走 |

顶栏可运行/暂停/单步、调速、手动派单、换随机种子重铺地图。

## 引擎架构(`src/engine/`)

```
types.ts        领域模型与 RuleConfig(全部策划可调规则)
config.ts       默认规则;一等加急限时 4320 分钟 = 3 个游戏日
rng.ts          mulberry32 种子随机 —— 同种子地图/事故完全可复现
map.ts          随机铺 30 驿站 + MST 保底连通的驿路网 + 马匹驿卒
travel.ts       纯函数行程原语:通行时间、体力消耗、有效速度、未来状态投影
reservations.ts 资源时间窗预约表(多单可在不同时间安全复用同一匹马)
planner.ts      Dijkstra 最省时选路 + 逐站马/驿卒资源选择 + 全程预约
simulation.ts   仿真主循环:恢复、天气、随机事故、到站履约、续程、重规划、统计
```

### 路线与换马是怎么算出来的(不写死)

1. **选路**:对当前驿路图跑 Dijkstra,边权 = 该路在当前天气、地形、公文紧急等级下的
   基础通行分钟数;断路直接从图中剔除,因此封路后自然绕路。
2. **选资源**:沿最省路径逐站,枚举该站所有「马 × 驿卒」组合,投影它们在出发时刻的
   体力/疲劳(含等待恢复),选出到达最早且**时间窗预约不冲突**的一组。
3. **预约而非独占**:每一程把 `[出发, 到达)` 时间窗写入预约表。同一匹马可被多份公文
   在互不重叠的时间段预约,从根上避免「一匹马同时驮两份公文」。
4. **只硬锁首程**:当前站→下一站的马与驿卒置 `assigned`;后续各程靠预约占位,
   公文到站后把下一程预约「转正」为硬锁。

### 途中事故与「不可撤回」

- **在骑的一程不可撤回**:正在赶路的公文,事故只顺延时刻、不换马不回站;
  历史 `Leg` 只追加(`arrivedAt` 落账),重规划只丢弃**未执行**的预案。
- **下雨断路**:道路置 `blockedUntil`,触发全量重规划;在骑程继续走完,未出发的预案绕开断路。
- **马病倒**:马置 `sick`,在骑则坚持到站后留下养病;相关公文到站续程时改派别的马。
- **劫道**:当前程 ETA 顺延一段滞留,人马路线不变。
- 道路恢复通行后自动再触发一次全量重规划。

### 性能

规划是 O(站点²) 的 Dijkstra + O(站均马匹 × 驿卒) 的逐站资源选择,30 站规模下单次规划亚毫秒级。
`npm run bench` 实测(本机):**502 单全量重规划 P95 ≈ 6ms**,远低于 100ms 红线,
余量留给更大地图或更密路网。

## 测试覆盖(`tests/`)

- 地图连通性、种子可复现、资产归属
- Dijkstra 选路、断路绕行、资源互斥、一等加急 3 日内可达、无路可走的优雅失败
- 接力送达、append-only 不可撤回、断路/病马/劫道重规划、超时统计、规则热更新
- 预约时间窗无冲突、重规划幂等
- 500 tick 混合事故 + 热更新长跑的全局不变量(锁一致、预案不走断路、资产清单自洽)
